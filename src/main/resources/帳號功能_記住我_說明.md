# 帳號功能說明：記住我（登入狀態）

> 對象：會員（USER）、小農（FARMER）的本地帳號登入
> 做法：登入時多帶一個 `rememberMe` 旗標，依勾選與否設定
> 「session 多久沒操作就過期」。

---

## 一、重要觀念：記住我記的是「登入狀態」，不是密碼

⚠️ 「記住我」**不會**也**不該**把密碼存在前端或瀏覽器。
它的真正意思是：**讓登入狀態（session）維持比較久**，
這樣使用者下次回來不用重新登入。

本專案是「session 登入」：登入成功後狀態存在伺服器的 session，
瀏覽器只拿到一個 `JSESSIONID` cookie 當作「鑰匙」。
所以「記住我」就是去調整這個 session 的存活時間。

---

## 二、改了什麼

| 檔案 | 改動 |
|------|------|
| `dto/LoginRequest.java` | 新增 `boolean rememberMe` 欄位（會員 / 小農登入共用） |
| `controller/UserController.java` | 會員登入後依 `rememberMe` 設定 session 過期時間 |
| `controller/FarmerController.java` | 小農登入後依 `rememberMe` 設定 session 過期時間 |

核心程式（兩個 controller 一樣）：

```java
HttpSession session = request.getSession(true);
session.setAttribute(...);   // 存登入狀態

// 依「記住我」設定 session 多久沒操作就過期 (單位：秒)
if (log.isRememberMe()) {
    session.setMaxInactiveInterval(60 * 60 * 24 * 14);   // 勾記住我：14 天
} else {
    session.setMaxInactiveInterval(60 * 30);             // 不勾：30 分鐘
}
```

`setMaxInactiveInterval(秒)`：使用者多久沒有任何操作，session 就失效。
（有操作就會自動延長，所以「14 天」是指「連續 14 天都沒動作」才登出。）

---

## 三、登入 request body

`rememberMe` 是選填，不傳預設 `false`。

```json
{
  "email": "test@example.com",
  "password": "你的密碼",
  "rememberMe": true
}
```

會員登入：`POST /api/member/login`
小農登入：`POST /api/farmer/login`

---

## 四、測試方式

1. 用 `rememberMe: false` 登入 → 30 分鐘沒呼叫任何需登入的 API，
   再呼叫 `/api/member/me` 會得到 401（已登出）。
2. 用 `rememberMe: true` 登入 → 同樣情況可維持很久（14 天內沒動作才登出）。

> 為了方便測試，可暫時把 `60 * 30` 改成 `60`（1 分鐘）觀察效果，測完再改回來。

---

## 五、和 cookie 設定的關係（重要！）

目前 `application.properties` 有這行：

```properties
server.servlet.session.cookie.max-age=1d
```

這是 **cookie（鑰匙）在瀏覽器端能放多久**，目前是 1 天。
它和上面的 `setMaxInactiveInterval`（伺服器端 session 壽命）是兩件事：

- `setMaxInactiveInterval` → 伺服器：多久沒操作就把 session 丟掉。
- `cookie.max-age` → 瀏覽器：這個 cookie 過多久就自己刪掉。

**兩者取較短的那個生效。** 因為 cookie 目前固定 1 天，
所以即使「記住我」把伺服器 session 設成 14 天，
**關掉瀏覽器超過 1 天後，cookie 被刪，還是要重新登入。**

### 如果要讓「記住我」真的撐超過 1 天
要讓 cookie 也跟著變長，做法（擇一）：

1. **最簡單**：把 `application.properties` 的 `cookie.max-age` 直接調長
   （例如 `14d`），缺點是「不勾記住我」的人 cookie 也會放 14 天。
2. **較完整**：登入時用程式自己寫一個 `JSESSIONID` cookie，
   依 `rememberMe` 給不同 `max-age`（勾 → 14 天；不勾 → 不設，關瀏覽器就刪）。
   這需要手動操作 Cookie，屬於進階寫法，目前先不做。

目前版本以「伺服器端 session 壽命」控制為主，已能達到
「勾了比較久、不勾比較短」的效果；要不要再延長 cookie 可之後再決定。

---

## 六、為什麼不用 Spring Security 內建的 rememberMe()

Spring Security 有內建 `rememberMe()`，但它要搭配內建的表單登入
（`formLogin` / `UsernamePasswordAuthenticationFilter`）才會自動觸發。
本專案是在 controller 裡「手動」建立登入狀態（自己 new Token、自己存 session），
內建機制不會被觸發，硬接會很複雜（還要橋接三種身分的 UserDetailsService）。
所以改用「自己控制 session 壽命」這個最貼近現況、最單純的做法。
