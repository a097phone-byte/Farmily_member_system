# 帳號功能說明：記住我（登入狀態）

> 對象：會員（USER）、小農（FARMER）的本地帳號登入
> 做法：登入時多帶一個 `rememberMe` 旗標，依勾選與否設定
> 「session 多久沒操作就過期」。

---

## 一、重要觀念：記住我記的是「登入狀態」，不是密碼

⚠️ 「記住我」**不會**也**不該**把密碼存在前端或瀏覽器。
它的真正意思是：**讓登入狀態（session）維持比較久**，
這樣使用者下次回來不用重新登入。

本專案是「session 登入」：登入成功後狀態存在伺服器的 session，
瀏覽器只拿到一個 `JSESSIONID` cookie 當作「鑰匙」。
所以「記住我」就是去調整這個 session 的存活時間。

---

## 二、改了什麼

| 檔案 | 改動 |
|------|------|
| `dto/LoginRequest.java` | 新增 `boolean rememberMe` 欄位（會員 / 小農登入共用） |
| `controller/UserController.java` | 會員登入後依 `rememberMe` 設定 session 過期時間 + cookie 壽命 |
| `controller/FarmerController.java` | 小農登入後依 `rememberMe` 設定 session 過期時間 + cookie 壽命 |
| `util/SessionCookieSupport.java`（新增） | 共用工具：勾記住我時補寫一個帶 `Max-Age` 的 persistent JSESSIONID cookie |

核心程式（兩個 controller 一樣）：

```java
HttpSession session = request.getSession(true);
session.setAttribute(...);   // 存登入狀態

// 依「記住我」設定 session 多久沒操作就過期，並決定 cookie 要不要寫進硬碟
if (log.isRememberMe()) {
    session.setMaxInactiveInterval(60 * 60 * 24 * 14);   // 勾記住我：server session 14 天
    SessionCookieSupport.writeRememberMeCookie(session, httpResponse); // 補寫 persistent cookie
} else {
    session.setMaxInactiveInterval(60 * 30);             // 不勾：30 分鐘 (沿用預設 session cookie)
}
```

`setMaxInactiveInterval(秒)`：使用者多久沒有任何操作，session 就失效。
（有操作就會自動延長，所以「14 天」是指「連續 14 天都沒動作」才登出。）

---

## 三、登入 request body

`rememberMe` 是選填，不傳預設 `false`。

```json
{
  "email": "test@example.com",
  "password": "你的密碼",
  "rememberMe": true
}
```

會員登入：`POST /api/member/login`
小農登入：`POST /api/farmer/login`

---

## 四、測試方式

1. 用 `rememberMe: false` 登入 → 30 分鐘沒呼叫任何需登入的 API，
   再呼叫 `/api/member/me` 會得到 401（已登出）。
2. 用 `rememberMe: true` 登入 → 同樣情況可維持很久（14 天內沒動作才登出）。
3. **關瀏覽器測試**：在瀏覽器登入後完全關閉再重開、打開 `/api/member/me`：
   - 勾記住我 → 仍是登入狀態（JSESSIONID 帶 `Max-Age`，沒被刪）。
   - 不勾 → 變 401（session cookie 已隨瀏覽器關閉刪除）。
   （可在 DevTools → Application → Cookies 看 JSESSIONID 有沒有 `Expires / Max-Age` 來確認。）

> 為了方便測試，可暫時把 `60 * 30` 改成 `60`（1 分鐘）觀察效果，測完再改回來。

---

## 五、和 cookie 設定的關係（重要！）

「記住我」其實同時控制**兩件事**，缺一不可：

- `setMaxInactiveInterval` → 伺服器：多久沒操作就把 session 丟掉。
- cookie 的 `Max-Age` → 瀏覽器：這個 JSESSIONID cookie 過多久就自己刪掉。

**兩者取較短的那個生效。** 所以光把伺服器 session 設成 14 天還不夠：
Tomcat 預設發的是「session cookie」（沒有 `Max-Age`），**一關掉瀏覽器就被刪**，
那不管伺服器 session 多長都得重新登入。要「關瀏覽器後仍記得」，
就得讓 cookie 也帶 `Max-Age`、寫進硬碟（persistent cookie）。

### 本專案的做法（做法 B：依勾選區分 cookie 壽命）

不是用 `application.properties` 的全域 `cookie.max-age`（那會讓不勾的人也被放長），
而是登入時**用程式自己依 `rememberMe` 寫 JSESSIONID cookie**：

| 情境 | server session | JSESSIONID cookie | 關瀏覽器後 |
|------|---------------|-------------------|-----------|
| **勾記住我** | 14 天 | 帶 `Max-Age=14天`（寫進硬碟） | **仍記得** ✓ |
| 不勾 | 30 分鐘 | 預設 session cookie（無 `Max-Age`） | 即刪，要重登 |

實作放在 `util/SessionCookieSupport.writeRememberMeCookie(...)`，只在勾記住我時呼叫。

**為什麼覆蓋得了 Tomcat 預設那份 cookie？**
呼叫 `request.getSession(true)` 當下，Tomcat 已把它那份「無 Max-Age」的
`Set-Cookie` 加進回應；我們在那之後才 `addHeader` 寫同名同 `path=/` 的 cookie，
這份排在後面，瀏覽器對同名 cookie 採用較後者，所以帶 `Max-Age` 的這份生效。
cookie 的 `HttpOnly / Secure / SameSite=Lax` 都和 `application.properties` 全域設定一致。

> 注意：`application.properties` 已**不再**設 `server.servlet.session.cookie.max-age`，
> 改由程式依勾選控制。Secure cookie 在 `http://localhost` 因瀏覽器有 localhost 例外仍可用；
> 若改用區網 IP 走 http 測試，Secure cookie 不會送出，這點要留意。

---

## 六、為什麼不用 Spring Security 內建的 rememberMe()

Spring Security 有內建 `rememberMe()`，但它要搭配內建的表單登入
（`formLogin` / `UsernamePasswordAuthenticationFilter`）才會自動觸發。
本專案是在 controller 裡「手動」建立登入狀態（自己 new Token、自己存 session），
內建機制不會被觸發，硬接會很複雜（還要橋接三種身分的 UserDetailsService）。
所以改用「自己控制 session 壽命」這個最貼近現況、最單純的做法。
