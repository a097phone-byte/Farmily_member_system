# Farmily 使用者服務 — 專案結構

> Spring Boot 3 + Spring Security（session 登入）+ Spring Data JPA(MySQL)。
> 一次性 token（Email 驗證 / 忘記密碼）改存 **Redis（Jedis）**。
> 前端採**混合架構**：
> - **會員 / 小農**為 Vue 3 CDN（Options API），放在 `src/main/resources/static`（走 `/api/**` JSON）。
> - **管理員後台**改用 **Thymeleaf 伺服器端渲染**，樣板放在 `src/main/resources/templates/back-end/admin`（走 `/admin/**`）。
>
> 分三種身分：**會員（Member / USER）**、**小農（Farmer / FARMER）**、**管理員（Admin / ADMIN）**，
> 各自有獨立的 Entity、UserDetails、UserDetailsService 與安全過濾鏈。

## 四、命名與分層慣例

- **Controller**：只負責收 request、呼叫 service、回傳（前台 `@RestController` 回 `ResponseEntity`；後台 `@Controller` 回 view 名稱 + `ModelMap`）；不放商業邏輯。
- **Service**：商業邏輯都在這層；複雜的有「介面 + `impl`」，單純共用工具則單一類別。**前台 API 與後台 Thymeleaf 共用同一套 Service。**
- **DTO 命名**：`XxxRequest`（進）、`XxxResponse`（出）。
- **三身分對稱**：Member / Farmer / Admin 各有獨立的 UserDetails、UserDetailsService、FilterChain。
- **前後端分工**：會員 / 小農為 **Vue SPA**（走 `/api/**` JSON，session cookie，CSRF 關）；管理員後台為 **Thymeleaf 伺服器端渲染**（走 `/admin/**`，`@Controller` 回頁面 + 表單 POST，formLogin + CSRF 開）。
- **前端元件命名**：以「身分前綴 + 功能」命名（如 `MemberPassword`、`FarmerLogin`），認證共用流程不加身分前綴。

## 五、需注意的路徑不一致（建議後續整理）

- **`com.farmily.util.HibernateUtil`** 不在 `com.farmily.user.*` 底下，且它是「**手動建立 Hibernate `SessionFactory`（讀 `hibernate.cfg.xml`）的 Singleton**」——
  與本專案採用的 Spring Boot + Spring Data JPA 完全是兩套機制，目前看起來沒有被任何地方使用，疑似學習階段遺留。
  建議確認後**移除**，或若真的要用，至少搬進一致的套件並說明用途。
- **`store.js` 殘留的後台方法**（`adminLogin` / `adminFetchMe` / `adminUpdateName` / `adminHasPerm`）在後台改 Thymeleaf 後已無人呼叫，屬無害死碼，可擇機清除。
