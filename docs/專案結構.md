# Farmily 使用者服務 — 專案結構

> Spring Boot 3 + Spring Security（session 登入）+ Spring Data JPA(MySQL)。
> 前端為純 CDN Vue 3（Options API），放在 `src/main/resources/static`。
>
> 分三種身分：**會員（Member / USER）**、**小農（Farmer / FARMER）**、**管理員（Admin / ADMIN）**，
> 各自有獨立的 Entity、UserDetails、UserDetailsService 與安全過濾鏈。

---

## 二、後端套件（`com.farmily.user.*`）

分層：`controller → service(介面+impl) → repository → MySQL`；DTO 負責進出資料形狀，Entity 不直接外露。

### 2-1. `UserApplication`（根）
| 類別 | 說明 |
|------|------|
| `UserApplication` | Spring Boot 進入點（`@EnableAsync` 啟用非同步寄信） |

### 2-2. `controller` — REST 入口
| 類別 | 路徑前綴 | 說明 |
|------|----------|------|
| `UserController` | `/api/member` | 會員 註冊 / 登入 / 個資 / 改密碼 / Google 登入 |
| `FarmerController` | `/api/farmer` | 小農 註冊 / 登入 / 農場資料 / 重新送審 / 改密碼 |
| `FarmerApplicationController` | `/api/farmer/application` | **免登入**小農申請：查審核狀態、退件後重新送審 |
| `AuthController` | `/api/auth`、`/api/logout` | 三身分共用登出、Email 驗證、忘記/重設密碼、重寄驗證信 |
| `CityDistrictController` | `/api/city-districts` | 註冊表單用的縣市/行政區下拉 |
| `AdminController` | `/api/admin` | 管理員登入 / 自身資料 |
| `AdminUserController` | `/api/admin/members` | 管理員管理會員 |
| `AdminFarmerController` | `/api/admin/farmers` | 管理員管理小農 |
| `AdminReviewController` | `/api/admin/reviews` | 管理員審核小農申請（核准 / 退件） |
| `GlobalExceptionHandler` | — | 統一把例外轉成 HTTP 狀態碼（401/404/409…） |

### 2-3. `dto` — 請求 / 回應物件
| 領域 | 類別 |
|------|------|
| 會員 | `UserRegisterRequest`、`UserUpdateRequest`、`UserProfileResponse` |
| 小農 | `FarmerRegisterRequest`、`FarmerProfileUpdateRequest`、`FarmerResubmitRequest`、`PublicFarmerResubmitRequest`、`FarmerProfileResponse`、`FarmerReviewResponse` |
| 管理員 | `AdminCreateRequest`、`AdminUpdateRequest`、`AdminSelfUpdateRequest`、`AdminProfileResponse`、`ReviewRejectRequest`、`StatusUpdateRequest` |
| 認證 / 共用 | `LoginRequest`（含 `rememberMe`）、`ChangePasswordRequest`、`ForgotPasswordRequest`、`ResetPasswordRequest`、`ResendVerificationRequest` |
| OAuth | `GoogleLoginRequest`、`GoogleTokenInfo`、`OAuthUserInfo` |
| 地區 | `CityDistrictResponse` |

### 2-4. `model` — JPA Entity（對應資料表）
| 類別 | 說明 |
|------|------|
| `User` | 會員（含 `authProvider` LOCAL/GOOGLE、`emailVerified`） |
| `Farmer` | 小農（含審核狀態 `farmerStatus`、`emailVerified`） |
| `FarmerReview` | 小農每輪審核快照（含證明檔 LONGBLOB，保留完整修訂history） |
| `Admin` | 管理員 |
| `AdminRole` | 管理員角色 |
| `AdminPermissionRole` / `AdminPermissionRoleId` | 角色↔權限關聯表（複合主鍵） |
| `AccountToken` | 一次性 token（Email 驗證 + 忘記密碼共用一張表） |
| `CityDistrict` | 縣市 / 行政區 |
| `SpendingTier` | 會員消費級距 |

### 2-5. `repository` — Spring Data JPA
`AccountTokenRepository`、`AdminRepository`、`CityDistrictRepository`、`FarmerRepository`、
`FarmerReviewRepository`、`SpendingTierRepository`、`UserRepository`（每個 Entity 一支）。

### 2-6. `security` — Spring Security
| 類別 | 說明 |
|------|------|
| `UserSecurityConfig` | 四條 `SecurityFilterChain`（admin / farmer / member / 預設）、session、cookie、SessionRegistry |
| `MemberUserDetails` / `FarmerUserDetails` / `AdminUserDetails` | 三身分各自的登入身分包裝 |
| `GoogleTokenVerifier` | 驗證 Google id_token |
| `security.service.*` | `MemberUserDetailsService`、`FarmerUserDetailsService`、`AdminUserDetailsService`（依 email 載入帳號） |

### 2-7. `service` — 商業邏輯（介面 + `impl`）
**有介面 + 實作（`service.impl`）：**
| 介面 | 實作 | 說明 |
|------|------|------|
| `UserService` | `UserServiceImpl` | 會員註冊 / 登入 / 改密碼 / OAuth |
| `FarmerService` | `FarmerServiceImpl` | 小農註冊 / 登入 / 重新送審 / 改密碼 |
| `FarmerApplicationService` | `FarmerApplicationServiceImpl` | 免登入的審核查詢 / 重送審 |
| `AdminService` | `AdminServiceImpl` | 管理員自身 |
| `AdminMemberService` | `AdminMemberServiceImpl` | 管理員端會員管理 |
| `AdminFarmerService` | `AdminFarmerServiceImpl` | 管理員端小農管理 |
| `AdminReviewService` | `AdminReviewServiceImpl` | 管理員端審核核准 / 退件 |
| `CityDistrictService` | `CityDistrictServiceImpl` | 縣市行政區查詢 |

**單一類別（無介面，跨身分共用）：**
| 類別 | 說明 |
|------|------|
| `EmailService` | 實際寄信（驗證信 / 重設信 / 密碼變更通知，`@Async`） |
| `EmailVerificationService` | Email 驗證：寄信、驗證、重寄 |
| `PasswordResetService` | 忘記密碼：寄重設信、用 token 重設 |
| `TokenService` | 產生 / 驗證一次性 token |
| `EmailUniquenessChecker` | 跨 User/Farmer/Admin 三表檢查 email 唯一 |
| `SessionService` | 登入時登記 session、改/重設密碼時讓 session 失效 |

### 2-8. `util`
| 類別 | 說明 |
|------|------|
| `util.SessionCookieSupport` | 「記住我」時寫帶 `Max-Age` 的 persistent JSESSIONID cookie |

## 四、命名與分層慣例

- **Controller**：只負責收 request、呼叫 service、回 `ResponseEntity`；不放商業邏輯。
- **Service**：商業邏輯都在這層；複雜的有「介面 + `impl`」，單純共用工具則單一類別。
- **DTO 命名**：`XxxRequest`（進）、`XxxResponse`（出）。
- **三身分對稱**：Member / Farmer / Admin 各有獨立的 Controller、UserDetails、UserDetailsService、FilterChain。
- **前端元件命名**：以「身分前綴 + 功能」命名（如 `MemberPassword`、`FarmerLogin`），認證共用流程不加身分前綴。

## 五、需注意的路徑不一致（建議後續整理）

- **`com.farmily.util.HibernateUtil`** 不在 `com.farmily.user.*` 底下，且它是「**手動建立 Hibernate `SessionFactory`（讀 `hibernate.cfg.xml`）的 Singleton**」——
  與本專案採用的 Spring Boot + Spring Data JPA 完全是兩套機制，目前看起來沒有被任何地方使用，疑似學習階段遺留。
  建議確認後**移除**，或若真的要用，至少搬進一致的套件並說明用途。
